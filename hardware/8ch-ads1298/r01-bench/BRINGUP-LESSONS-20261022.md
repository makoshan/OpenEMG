## A｜走过的路

```
[阶段1 断电检查] ✓
   ↓ J3 误插杜邦线 → 电池被拖到 0V；拔掉后恢复
[阶段2 首次上电] ✓ 电池供电时模拟电源默认关断
   ↓ XIAO 只接了 BAT+、没接地 → 不通电；补地线后 3V3 正常
[阶段3 启动时序] ✓ P03 只开电源固件跑通；示波器地夹没夹只看到 50Hz，最后跳过；VCAP1 由 Mako 豁免
[阶段4 蓝牙版] ID/回读过，DRDY=0（故障码 8）
   ↓ D1/D3 杜邦线松动、电池深放到 3.1V，故障码在 8/4/3/断连之间跳
   ↓ 改为 USB 固件 F05-USB，加 DIAG/PWR1/BLND 自诊断
[定位] AVDD 5.00V、ADS 在转换、D6 被 U3 压低 → DRDY 网络一直为低
   ↓ 盲读发现：CS 低、不给时钟时，DOUT 会跟着 DRDY 变
[DOUT 代 DRDY] 约 0.2–1% 漏沿 → 补漏帧守卫 → 一次 DMA 读帧 + GPIO 锁存 → 2 分钟 240036 帧推算 0
   ↓ 8 路测试台阶不一致 → 用电源/温度通道核：采集链准，是测试源本身不准
[短接本底] 2k/4k 各 62s 通过；4k 要 4MHz SPI
   ↓ Mako 问“是不是程序问题” → D6 加锁存与正反对照 → 确认 D6 采集中从未变高
[DRDY 自检] 固件启动后自动判断，不通就用 DOUT
```

## D｜下一版板子改进（按优先级）

### P0：DRDY 这一路
1. **ADS 的 DVDD 用 3.3V，和主控同一电压，SPI 和 DRDY 直连，去掉 U2/U3 电平转换**。ADS1298 的 DVDD 允许 1.65–3.6V；具体电源组合（AVDD−DVDD 范围、去耦）下一版设计时再核，未核。
2. 还要电平转换的话，用引脚露在外面的封装（TSSOP），不用 QFN。R01 的 U3 是 QFN，20 脚两侧是 19 脚（GND）和 21 脚，底下是地焊盘，出了问题看不到也量不到。
3. DRDY 两端（ADS 侧、MCU 侧）各放一个带丝印的测试点；单向关键信号不要紧挨地脚。
6. ADS 的 TESTP/TESTN（PACE_OUT）脚悬空或按手册处理，**不要接 AVDD**：R01 接了，内部测试信号被拉住，测试源不能当幅度基准。
4. 固件默认带“DRDY 自检，不通就自动改用 DOUT”（`firmware-f05-usb` 已实现）。
5. 想戴着用 USB 传数据，就加 USB 隔离并保留互锁；否则只用电池加无线。R01 上“插 USB 就得关互锁”只能离体用。

### P0：隔离与互锁（通用做法，2026-10-22 Mako 定写入）
原则：贴皮肤那一侧（电极、AFE）任何时刻都不能和可能接市电的东西（USB、调试器、充电器、示波器）有导电通路。三种做法：

| 做法 | 隔离位置 | 戴着能 USB 传数据 | 代价 |
|---|---|---|---|
| ① 电池 + 无线 + VBUS 硬件互锁 | 不隔离，插 USB 即 AFE 断电 | ✗ 只走无线 | 零额外器件 |
| ② 板上 USB 隔离（ISOUSB211，或 ADuM4160 + 隔离电源） | USB 口 | ✓ | 多 2 颗芯片 + 隔离电源，手腕放不下 |
| ③ AFE 小岛隔离（数字隔离器隔 SPI 和 DRDY，AFE 独立供电） | AFE 与主控之间 | ✓ 任何接口都安全 | 中等，医疗设备做法 |

定法：**手环本体用 ①；台架上要 USB 采集时，外接通用 USB 隔离器加台架模式跳线**。一个隔离器给所有板子用（2026-10-22 选定正点原子 HUB23：2000V 隔离、2.5W 隔离电源，商品页标称，未实测，工业级，不是医疗认证）。以后真要戴着用 USB 长时间传数据，再升级到 ③。
1. VBUS 互锁做成纯硬件（VBUS 经 MOS 关 AFE 电源），固件不能绕开；主控能回读互锁状态。
2. 台架模式用跳线或拨码，丝印 BENCH ONLY，固件读得到，并在元数据里标 bench；读不到时只允许电池模式采集。外接隔离器时才打开台架模式。
3. 电极输入的限流电阻放在 ESD 前面（R01 是 ESD 在前，单故障路径没放行）；每路串联电阻按单故障电流 ≤10µA 计算（限值转引，标准原文未读）。
4. 每个电极口旁留漏电流测试位（能接 1kΩ 负载），测漏电流不用飞线。
5. 不管用哪种隔离器，上皮肤前都要实测漏电流；隔离器标称耐压不能代替这一步。

### P0：去掉“人手插线”
- 主控直接贴在板上（二代已定 CH585M），或者用带锁扣的板对板连接器 / FPC。关键信号不走 2.54mm 杜邦线。
- 板上自带 3V3 LDO，不靠模块经长线供电（R01 的 J1-1 量到过 2.9V，离 U12 门限 3.07V 很近）。
- 电极口和 MCU 口在外形上做防呆，杜邦头插不进 J3。

### P0：板子能自己报告状态
- VBAT 分压、3V3、AVDD、DVDD 或 PG、U7_EN、DRDY 都接到 MCU 上，固件可以直接回读。
- 只有一端驱动的信号加 100k 级下拉，这样诊断分得清“悬空”和“被驱动”。
- 两颗小电流指示灯：模拟电源已开、DRDY 活动。

### P1：测试点、台架模式、焊接
- 测试点全部印丝印编号，焊盘 ≥1.5mm 或用测试环；补齐 DRDY（两侧）、MISO、SCLK、VBAT、3V3，VCAP1 保留（R01 已有 TP8）；多放几个地测试点，留一个地夹专用接地柱。
- 保留 USB 互锁，另加台架模式跳线或拨码，丝印写“BENCH ONLY / 不上人体”，并且固件能读到它的状态，这样不用靠拔线；台架模式下固件拒绝接电极，或者给出警告。
- 电池口防反接；充电状态接到 MCU，用电压判断，不看灯。
- 细间距件做 AOI，或首板做 X-ray；首板到手先用放大镜检查细间距件的焊点再上电；BOM 上的“草案新增”件（如 R27）逐个核对贴上了没有。

## E｜固件和工具（下一版直接沿用）

- **首板先刷 USB 诊断固件**（`firmware-f05-usb`）：`DIAG` 查接线，`PWR1` 只开电源，`BLND`/`HOLD` 盲读，`TST1`/`SHT1` 内部信号，`EXR1` 接信号源，`Waavv` 采集中改内部寄存器。每个停机都报 `diag:3`（沿间隔、推算数）、`diag:4`（DOUT 时序）、`diag:7`（DRDY 来源）。
- 每个状态帧带 AVDD、VBAT、VDD、OE_N 读数；故障码带上当时的读数；时间戳用硬件定时器。
- 窄脉冲（DRDY 不读时只有约 2µs）用 GPIO 锁存抓，不靠轮询；做负结果前，先做正反对照。
- 增益和参考用电源通道和温度通道核，不用内部测试源。
- 主机判定把“传输对”（CRC）和“采样对”（无推算、无缺口、正常停机）分开写。
- 工具链固定为原生 arm64；蓝牙固件出故障后要继续广播；“先扫描再连接”的脚本要入库。

## F｜流程和边界

```
断电检查 → 首次上电 → DIAG → PWR1 → ADS ID/回读 → 盲读 → DRDY/采样 → 内部信号 → 外部信号源 → 漏电流 → 安全门 → 人体
```

- 每一步只改一个变量；改过线就从 DIAG 重来。
- 负结果先做阳性对照（例：示波器先量已知的 3.9V）；实测和推断分开写，推断错了就明确作废。
- 改共享源文件之前，先查下游有没有在用。
- 让 Mako 量一个点之前，先给一张标好位置的实拍图。
- **互锁失效（J1-12 接地）时，J3 只许空着或接信号源加分压器，绝不接人体。** 上人体前至少要：恢复互锁、改用电池加无线、测漏电流、过 `v12-a/PLAN.md` 第 4 条安全门。

### 漏电流简化方案（2026-10-23 提出，待复核，未实测）

1. **查桥接（替代 A 组）**：J3 空着、EXT1 采集。某个输入桥到了电源，那一路会打满量程，软件一眼看出（Claude 做，Mako 不动手）。局限：P、N 同时桥到同一电源的两重故障看不出；J3-17 不在 ADS 通道里，靠物理拆掉排除。
2. **只测要用的脚（替代 B 组）**：第一次只用 CH1，J3-1、J3-2 连起来经 1 kΩ 到 TP10，EXT1 采集时读 DC、AC 各一个数，≤ 2 mV。
3. **贴的时候实时盯**：万用表 µA 档串在 J3-1 电极线上，只用一对电极时回路电流全经过这块表；超过 10 µA 或刺痛就摘。

### 一镜像两通道与蓝牙 2048 帧队列（2026-10-24 实测）

- 固件 `firmware-r01-dual/`（build d267b2c490298e6c）：开机看 VBUS，插 USB 走串口，只接电池走蓝牙；运行中插拔 USB 整片复位。换模式不再刷机。
- USB 模式读回版本号和 transport=usb_cdc；发 EXR1 后没有出现样本帧，外部输入被拒。
- 蓝牙模式经 C6 接收器跑 SHT1 10 分钟：1,199,631 帧，缺 0、故障 0，计数闭合，STOP 正常收尾。队列峰值 69/2048，最长发送间隔 34.7 ms。期间 Mako 手靠近过板子，手机没测。512 帧时的 Overrun 这次没有复现，但峰值 69 本来就在 512 以内，不能证明非要 2048。
- 坑：两份程序里都有 `struct BoardHal`，链接器会静默只留一份，结果 USB 模式跑的是蓝牙版 HAL，启动全部 Cancelled。自检查不出来，是独立复核看 elf 抓到的。现在构建时改名，并用 nm 检查两边有没有同名外部符号。
- 坑：USB 版 AVDD 起不来那次，原因是 J2 电池没插（模拟电源只由电池供电），另外 J1-12 还要跨接 J1-14。插着 USB 时电池读数在 3.58–3.97 V 之间跳，就说明没接电池。
- 坑：只能充电的数据线插上后，Mac 上什么设备都不出现；一插就看 `ioreg -p IOUSB`。C6 不应答时用 `~/.espressif/python_env/idf6.1_py3.14_env/bin/python -m esptool --chip esp32c6 -p <口> --after hard-reset chip-id` 复位。

### 时间账：6 天去哪了（2026-10-24，原始会话时间戳，两人独立算）

来源：主调试会话 245 条 Mako 消息的时间戳（不含 Codex 会话、子代理）。台前 = 相邻消息间隔 <60 分钟的累加。分段两人各自独立划，总数一致，分类占比差几个点。

| 项 | 数 |
|---|---|
| 日历 | 144.5 小时（10-18 22:46 → 10-24 23:13） |
| 台前 | 30.6 小时（21%） |
| ≥3 小时空档 | 11 段，100.3 小时（69%） |

台前分类（两份分段的区间）：看不见测点 17%；硬件设计缺陷绕路 16–19%；安全门 15–19%；电源/电池 12%；刷机 6–12%；接线 9–18%；无线传输 4–8%。

结论：日历慢主要因为只在晚上有人；台前慢主要因为 AI 看不见、摸不着实物，每个读数、每次刷机、每根线都要人来回一趟。按 R01 的做法，下一块板还会再来 90 次往返。

下一块板（C06/C07）的改法，按省时排序（估算，未实测）：
1. 刷机不用人：`host/r01_flash.py` 走 1200 波特率触发 + 串口 DFU（串口 DFU 不出 U 盘，别等盘），已有会话实测过；R01 本周至少 6 轮双击是多余的。
2. 板子自己报读数：本周手量过的点（3V3、VBAT、AVDD、DVDD、PG、OE_N、U7_EN、J1-12 状态）尽量都接到 MCU ADC / GPIO，DIAG 一条命令全回；互锁加可读的台架模式跳线（见 E 节）。
3. 不用杜邦线：带键位的成品线束，到货先跑一遍线束通断自检。
4. 设计缺陷前置：DRDY 路径、TESTP 接法、互锁旁路，在打样前由独立代理按数据手册逐条核，R01 这三处都是事后才发现的。
5. 安全门前置：漏电流测法和夹具在打样前定稿，R01 的测法改了两次。
6. 一块板只有一个会话在用：HANDOFF 顶部写设备在谁手里；10-24 两个会话先后刷同一块 R01，互相覆盖。

### 首次人体与给 C06/C07 的改进（2026-10-25 实测）

**结果**：电池 + 蓝牙 + C6 接收器，表带干电极只接 CH1，同侧前臂，EXT1（右腿驱动关、J3-17 空）。89 秒 177,969 帧，缺 0、故障 0；Mako 未报不适。**链路和安全门通过，但握拳分辨不出**。

| 指标（20–450 Hz 带通 + 50 Hz 谐波陷波，同一套脚本） | 唯理 WL8（结印 15 段中位） | R01 首测 CH1 |
|---|---|---|
| 放松滤波后 RMS | 54–67 µV | 432 µV |
| 原始 50 Hz | 126–278 µV | 9,938 µV |
| 用力 ÷ 放松 | 9–28 倍（五雷） | 1.2 倍（握拳） |

R01 离体短接本底 2.8 µV，问题在电极到人体这段：没有参考电极（人体共模浮动）、干电极接触不稳、引线长且没绞。唯理幅度单位是自报 µV，比较看比值。

**给 C06/C07 的改法（按影响排序；均未在 C06/C07 实测）**

1. **参考 / 右腿驱动电极是必需件，不是可选件**：板子、表带、线束都要把它当第 3 根常规电极设计；固件的 RLD_SENSP/N 只选真正接了电极的通道（R01 现为 0xFF，只接 CH1 时其余 7 路悬空会把 RLD 拉偏）；RLD 串联限流的两颗电阻焊盘间距要拉开（R01 的 R5 两端只隔 0.25 mm，桥接后单故障 28 µA，余量小），安全分析按“RLD 常开”做，不再靠拆 J3-17。
2. **蓝牙余量**：2 kHz × 8 路 × 24 位要 250 包/s，R01 实测上限约 274；C6 放 5 米外吞吐掉到满速的 10–20%，队列满报 Overrun（故障 7），状态读取也出错。C07 16 路要 333 包/s，必须用 16 位打包或降采样，并按“接收器在 5 米、隔着人体”做验收。主机在拥塞时报的是“状态长度错误”，要改成直接报链路吞吐低。
3. **电池电量要能读、低电要先停**：10-25 08:52 采集中模拟电源掉电（故障 3），充电后不复现；R01 读不到电池电压。C07 已有 VBAT_SENSE，固件要在采集前和采集中检查，低于阈值拒绝开始。
4. **电极到板的接口要成品化**：这次表带 FPC 的细线曾被直接焊到板上 J2 旁（拆掉后才继续）、有裸端子挨着电池线。C07 的电极 FPC/线束要带键位、不能随手焊到板上；漏电流测试夹具（电极口经 1 kΩ 到 GND 的插头）做成配件。
5. **干电极要压紧、引线绞合短**：动作伪迹（0–20 Hz）达几百 mV。表带压力、电极材料和引线长度当成设计项，而不是佩戴说明。
6. **台架自动化已经能用**：一镜像两通道 + `host/r01_flash.py` 免手刷机；`eyes` skill 能用大疆 Osmo 录像、按挂钟时刻抽帧读万用表；漏电流 AC 用手机视频逐帧读到 0.1 mV 分辨。C07 首刷见 `docs/c07-first-flash-20261025.md`。
7. **接收器 C6 会卡死**：本周多次，用 esptool 硬复位恢复；主机脚本应在开始前自动复位并检查应答。
